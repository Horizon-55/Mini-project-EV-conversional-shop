# Опис предметної області та меж контекстів (Bounded Contexts)
**Тема:** Проєктування та розробка баз даних для мікросервісної архітектури  
**Предметна область:** EV Conversion Shop (Інтернет-магазин та сервіс переобладнання автомобілів з ДВЗ на електротягу)

---

## 1. Загальний опис домену (Vision)
**EV Conversion Shop** — це платформа для ентузіастів, автомайстерень та приватних автовласників, які переобладнують класичні або серійні легкові автомобілі (наприклад, BMW E30, VW Golf Mk2, класичні позашляховики) на чисту електричну тягу. 

Система вирішує завдання підбору сумісних компонентів (електродвигуни, батарейні модулі, силові інвертори, перехідні плити під КПП, порти швидкої зарядки CCS2), оформлення замовлень на комплекти «під ключ» чи набори для самостійного складання (DIY Kit), а також забезпечує технічну спільноту платформою для обміну відгуками, динамометричними тестами, схемами підключення CAN-bus та реальними проектами конверсії.

---

## 2. Розподіл системи на Bounded Contexts (Межі контекстів)

Згідно з принципами **Domain-Driven Design (DDD)** та мікросервісним патерном **Database-per-Service**, систему розділено на три незалежні контексти, кожен з яких володіє власною базою даних і не має спільних зв'язків через зовнішні ключі (Foreign Keys).

```
+-----------------------------------------------------------------------------------+
|                            EV CONVERSION PLATFORM                                 |
+-----------------------------------------------------------------------------------+
        |                                     |                                 |
        v                                     v                                 v
+-----------------------+           +--------------------+          +---------------------+
| 1. ORDERING CONTEXT   |           | 2. CATALOG CONTEXT |          | 3. REVIEWS CONTEXT  |
| (Транзакційний контур)|           | (Довідниковий)     |          | (Спільнота / NoSQL) |
| SQL Server (Dapper)   |           | SQL Server (EF)    |          | MongoDB             |
+-----------------------+           +--------------------+          +---------------------+
```

---

### Контекст №1: Ordering Service (Керування замовленнями)
* **Технологія персистентності:** SQL Server (ADO.NET & Dapper) — процедурний стиль, строгі транзакції, блокування на рівні рядків `WITH (UPDLOCK)`.
* **Призначення:** Життєвий цикл замовлення від створення до доставки або скасування; фінансові та договірні зобов'язання.
* **Агрегат:** `Order` (корінь агрегату) + `OrderDetails` (1:1) + `OrderItems` (M:N).
* **Сутності контексту:**
  - `Customers` (Покупець / Контрагент) — базовий профіль для оформлення замовлення.
  - `Orders` — корінь агрегату; керує статусом (`Submitted` $\to$ `AwaitingValidation` $\to$ `StockConfirmed` $\to$ `Paid` $\to$ `Shipped` / `Cancelled`), містить `RowVersion` для запобігання конфліктам конкурентності.
  - `OrderDetails` (1:1) — адреса доставки, контактний телефон, модель автомобіля-донора (`TargetVehicleModel`), тип переобладнання (`DIY_Kit` / `Turnkey_Installation`).
  - `OrderItems` (M:N) — перелік замовлених вузлів. Зберігає **незмінний знімок (Snapshot)** назви та ціни товару на момент підписання угоди.
  - `Products` (Локальна репліка / Read Model) — локальна копія довідника компонентів без FK на сервіс Каталогу.
  - `OrderStatusHistory` — аудитний журнал переходів станів із фіксацією автора зміни та причини.

---

### Контекст №2: Catalog Service (Каталог компонентів та комплектів)
* **Технологія персистентності:** SQL Server (Entity Framework Core Code First + Fluent API).
* **Призначення:** Управління номенклатурою товарів, технічними характеристиками електротранспорту, категоріями, сумісністю та фотоматеріалами.
* **Агрегат:** `Product` (корінь агрегату) + `TechnicalSpecifications` (1:1) + `ProductImages` (1:N) + `ProductCategories` (M:N).
* **Сутності контексту:**
  - `Products` — корінь агрегату: унікальний артикул (SKU), базова вартість, поточний залишок на складі, статус доступності.
  - `Brands` (1:N до `Products`) — виробники компонентів (Nissan OEM, CATL, Sevcon/BorgWarner, Phoenix Contact).
  - `Categories` (M:N до `Products`) — рубрикатор каталогу (Електродвигуни, Батарейні модулі, Інвертори, Перехідні плити).
  - `ProductCategories` (M:N з власним станом) — проміжна таблиця, що містить дату прив'язки `DateAdded` та прапорець пріоритетної категорії `IsPrimary`.
  - `TechnicalSpecifications` (1:1 до `Products`) — глибокі технічні параметри: робоча напруга (V), пікова потужність (kW), ємність (kWh), вага (kg), тип охолодження (Liquid/Air).
  - `ProductImages` (1:N до `Products`) — галерея зображень товару з порядком відображення та мініатюрою.

---

### Контекст №3: Reviews & Community Service (Відгуки та спільнота)
* **Технологія персистентності:** MongoDB (NoSQL) — документо-орієнтована модель, динамічна схема, поліморфізм.
* **Призначення:** Збір відгуків покупців, польові випробування вузлів конверсії, динамометричні виміри, обговорення технічних труднощів та галерея готових проектів.
* **Колекції:**
  - `reviews` — оцінки компонентів. Використовує **Embedding** для автора та вкладених коментарів-відповідей, **Referencing** для посилання на форуми (`discussionId`), та **поліморфні поля** (для моторів — `dynoTestedTorqueNm`, для батарей — `realWorldRangeKm`, для плит — `gearboxModel`).
  - `discussions` — гілки технічного форуму для вирішення специфічних задач (наприклад, узгодження протоколів CAN-bus).
  - `conversion_showcases` — портфоліо реалізованих конверсій автовласників з вкладеними етапами проекту (`milestones`) та характеристиками.
